# Tilot 开发计划

更新日期：2026-09-21

本文记录实现顺序、每批工作边界和验收方式。产品范围以 [产品需求](./product-requirements.md) 为准，模块职责以 [技术设计](./technical-design.md) 为准，模型接入遵循 [DeepSeek 接入规范](./deepseek-integration.md)。未确认的技术选择单独列出，不作为已经确定的设计。

## 1. 开发目标和协作方式

首版完成一个可安装的 Windows 桌面 Agent：选择项目、对话、读取和搜索代码、执行开发命令、修改文件并查看差异，以及保存和继续任务。执行体验按开发者 Codex 截图中的“完全访问”模式，直接执行并展示结果与差异，不逐次弹窗。

- 主要使用 DeepSeek，只接入 Responses API；允许用户配置 baseURL。
- 使用 OpenAI SDK，优先复用 SDK 类型，不设计通用 Provider。
- 正式历史保留完整模型输出，包括 reasoning 项及其正文。
- 只操作用户选择的项目中的代码和相关文本配置文件。
- 参考 Pi，只提供 read、write、edit、shell 四个基础工具；shell 使用 PowerShell。目录枚举和搜索由命令完成，不另做搜索、Git、网页或 Office 专用工具。
- 界面布局、功能入口与交互以 Codex 为参照，不增加文件树；未覆盖的页面先与开发者确认。模型文件工具与界面功能分开实现。
- 每批完成一段连贯功能，通常包含几个相关函数或类型及必要测试，不再以单个简单函数作为默认停顿点。
- 单批以容易阅读和讲解为准；预计涉及多个模块的大范围改动时，先拆分，再与开发者确认。
- 每个函数、类型和接口写中文用途注释；复杂约束说明原因，不逐行翻译代码。
- 测试放在所属包的 `tests/` 下；优先覆盖关键业务与故障边界，不为简单包装、字段映射或同一种行为重复堆测试。
- 不增加没有实际调用需求的抽象或兜底；无效输入在负责该边界的模块处理，避免层层重复校验。
- 直接实现当前功能所需的正式逻辑，不写空实现、模拟业务占位或暂时绕过约束的版本；测试中的模拟不属于业务实现。
- 每批结束说明改动、关键代码、验证结果和未完成内容，等待开发者同意后进入下一批。批准本计划不等于批准一次完成全部阶段。

## 2. 已确认的目录和职责

```text
tilot/
├── apps/
│   └── desktop/
│       ├── src/          # React 界面
│       └── src-tauri/    # Tauri 桌面宿主
├── packages/
│   ├── server/           # 服务入口、模块组装、RPC 与生命周期
│   ├── agent-core/       # Agent 执行流程和状态调度
│   ├── context/          # 历史组织、上下文预算和压缩
│   ├── tool/             # 工具定义、校验、权限和执行
│   ├── store/            # 对话、配置、凭据和其他持久数据
│   ├── responses/        # SDK 客户端、流式请求和响应校验
│   └── protocol/         # UI 与 Server 共用的通信类型
└── package.json
```

不创建 runtime 包。Server 负责组装模块，Agent Core 负责业务调度。Protocol 不依赖文件系统、数据库或 SDK 客户端；UI 通过 Server 使用 Agent，不直接导入服务端实现。

内部模型数据复用 Responses 类型；UI 使用适合展示的通信数据。只有确实需要跨模块使用时才导出类型，不提前设计所有接口或建立通用框架。

## 4. 分阶段实施顺序

下表中的阶段可能包含多批代码。每批都单独讲解和确认，不将整个阶段作为一次提交规模。

| 阶段 | 主要工作 | 可观察的完成标准 |
| --- | --- | --- |
| 1. 完整模型响应 | 校验终态和输出、提取 function 调用、保留原始响应；补充事件序号和输出关联检查 | 不完整或冲突响应不会产生可执行工具调用，正常响应不丢失 reasoning |
| 2. Store 基础 | 确定存储方案；按实际需要实现配置、项目、任务、轮次、响应及工具结果的保存与查询；分开处理凭据 | 重启后可读取任务和完整模型历史，普通配置和日志不包含密钥 |
| 3. Context 基础 | 从持久记录构建 instructions 和 input，转换 SDK 历史项，校验调用与结果配对 | 多轮请求保持原始顺序，不产生孤立工具调用或丢失推理正文 |
| 4. 无工具 Agent 执行 | 实现开始、流式输出、保存成功响应、失败和取消；确定同一任务的运行互斥 | 一轮对话正确结束，失败片段不进入正式回放历史，取消后不再启动下一次请求 |
| 5. 桌面与服务贯通 | 确定 RPC 传输；实现必要协议、Server 入口、Tauri 服务进程管理和基本 React 对话界面 | 用户可配置连接、发起对话、看到流式输出并取消；桌面退出后子进程结束 |
| 6. 文件读取基础 | 实现文件工具路径边界、文本识别和 read 分段读取，不做文件树或目录枚举工具 | 按行返回文件内容，拒绝非法路径、内部链接及不支持的文件 |
| 7. 命令工具 | 实现 PowerShell shell、参数校验、取消、超时和输出限制 | 可列目录、搜索和运行开发命令，正确返回输出、退出状态及截断信息 |
| 8. 工具调用循环 | 将工具接入 Core，依序执行同一响应的全部调用，保存结果并构造下一次请求 | 模型可读取和搜索项目后作答；未知工具、参数错误、拒绝及取消均有配对结果 |
| 9. 写入与编辑工具 | 实现 write 完整写入、edit 精确替换，按已确认策略执行 | 歧义替换明确失败，实际写入结果被保存，不伪造成功 |
| 10. 工具与差异界面 | 参考 Codex 展示工具执行及文件差异，不增加逐次批准或固定批次提案流程 | 执行状态及变更可检查，失败可解释，运行可以取消 |
| 11. 任务交互与恢复 | 完成任务列表、切换、重启后继续、运行中补充需求、重复提交处理和中断恢复 | 切换任务不会串流；未决写入先核对，不因重试重复应用；补充输入在明确边界生效 |
| 12. 预算和长任务 | 实现输入预算、工具结果限制、上下文摘要、最大步骤、有限重试及 usage 记录 | 压缩不拆散工具消息组；达到限制可解释地停止；缺失用量标记未知 |
| 13. 发布验证 | 构建 UI 与服务、封装 Node.js 服务进程、打包 Tauri、完成 Windows 验收 | 在没有开发环境的 Windows 机器上可安装、启动、完成文件任务并正常退出 |

阶段 5 建立早期可用的对话界面，避免所有后端完成后才检查桌面通信。真实模型联调安排在连接配置可用之后，单独记录模型、地址和测试结果，不以本地模拟结果代替兼容性验证。

基础的取消和错误处理随所属功能实现；阶段 11、12 负责多任务恢复和完整策略，不将所有异常处理推迟到最后。

## 5. 接下来三批的具体范围

### 第 1 批：成功响应校验与工具调用提取

状态：已完成。入口为 `@tilot/responses/output` 的 `getResponseToolCalls`。流式校验器已在传出终态前调用此入口验证响应；后续 Agent Core 使用该入口获取工具调用。

位置：packages/responses。

- 接收终态事件携带的完整响应，校验 status 与终态含义一致。
- 校验首版使用的消息、reasoning 和 function_call 输出，识别不支持且影响执行的输出类型。
- 按输出顺序提取工具调用，检查必要字段及 ID，不将输出项 id 与 call_id 混用。
- 返回或保留 SDK 原始响应，不将全部输出压成一条文本，不改写 reasoning。
- 工具参数在本批保持原始 arguments 字符串；具体参数 schema 和授权由 Tool 校验。

验证正常文本、混合推理与工具调用、多个调用、重复或缺失 ID、失败和截断响应。业务代码保持几个相关函数，不同时接入 Core 或数据库。

### 第 2 批：补齐流式事件一致性

状态：已完成。每次请求创建独立的 ResponseStreamValidator；重复事件去重，输出按位置及标识关联，成功终态核对已完成输出。失败和截断仍保留诊断事件，不要求补齐成功输出。

位置：packages/responses。

- 检查一次请求内的 sequence_number 顺序，相同事件可去重，冲突事件报错。
- 检查工具事件的输出位置与标识关联，正确处理多个工具交错出现的事件。
- 明确增量内容只用于预览，完整响应才是保存和后续执行的依据；done 不重复追加。
- 保留现有取消、断流和资源释放行为，不增加自动重试。

验证重复、倒序、交错、终态不一致和中途取消。尽量使用终态完整响应，避免维护另一份没有必要的完整响应副本。

### 第 3 批：Store 的第一个完整功能

状态：普通配置读写已完成。开发者已确认配置和对话历史统一使用 SQLite，默认数据目录为 `%LOCALAPPDATA%\Tilot`。驱动采用 better-sqlite3；凭据按后续确认保存到同目录的 credentials.json。

位置：packages/store。

先确认存储方案和数据目录，再实现配置保存与读取，包括 baseURL、模型和应用限制。凭据存储采用单独边界；具体后端未确认前，不把密钥写入普通配置文件。其他实体等到使用时逐批添加。

验证重新打开存储后配置可恢复、无效配置不会覆盖有效配置。此批不一次性设计所有数据库表或编写整套 Store。

## 7. 验证和完成标准

每批按改动验证，避免只检查代码能否运行：

- 类型或实现有改动时运行类型检查；涉及响应、路径、写入、取消或状态转换时增加对应行为测试。
- 模型协议使用本地事件样本测试，文件行为使用临时项目测试；另行进行少量真实模型联调。
- 模拟数据只存在于测试中，正式功能不返回假成功或示例工具结果。
- 增加桌面功能后验证实际界面、通信和服务进程退出，不能仅以组件测试代替。
- 首版最终验收覆盖“打开项目 → 搜索和读取 → 修改文件 → 查看差异 → 运行验证 → 重启继续”。
- 对路径越界、外部修改冲突、断流、取消、写入部分失败和进程退出逐项验证。
- 只更新实际完成的进度，不将包目录存在、类型定义完成或测试替身通过视为功能已交付。

任务记录已完成：Thread 保存 id、title、可空 projectPath，以及毫秒时间戳 createdAt/updatedAt。不提供项目重新绑定或任务删除接口。

轮次与输入这一批已完成：Turn 保存任务归属、任务内序号、状态、起止时间和失败信息；TurnInput 保存首条及补充输入。状态从 running 进入 completed、failed、cancelled 或 interrupted，结束后不可改写。同一任务的运行互斥由 SQLite 唯一索引保证，不同任务的实际执行调度由 Core 决定。

模型响应与工具结果这一批已完成：每次请求单独保存为 ModelAttempt，inputThroughId 标记本次采用的用户输入边界；成功响应保留完整 SDK 输出和推理正文，其他终态记录仅供诊断。成功响应中的调用与响应原子保存，工具结果通过本地执行 id 和 call_id 配对且不可覆盖。未决调用会阻止该任务的后续请求，重启后须先核实，不能自动重跑。

阶段 3 的 Context 基础已完成：buildContext 读取指定任务截至目标运行轮次的全部分页历史，按成功请求的 inputThroughId 排列用户消息，每份响应紧接全部工具结果。复用 Responses 的响应校验和 SDK 的 toResponseInputItems，不修改原始存储。当前默认保留旧轮次未发送输入，当前轮次以调用方指定边界为准；尚无预算、摘要和 Skills 加载。

阶段 4 的无工具单轮执行已完成：runTurn 创建轮次和请求尝试，冻结输入与普通配置，传递流式事件并保存终态。失败和取消不会触发下一次请求；截断尝试保留 incomplete 状态，轮次记为 failed；意外工具调用只作诊断。成功终态落库后再通知。当前默认不同任务并行、系统策略由调用方传入，正式提示词尚未设计。

阶段 5 的第一批已完成：开发者选择标准输入/输出通信和本地文件凭据。已实现独立 Protocol 类型、Node 服务入口、行协议和四个任务接口；API Key 单独保存在 credentials.json，读取按服务地址匹配，未接入系统凭据管理器。服务收到输入结束后关闭数据库；尚未接入 Tauri 宿主。

配置与凭据 RPC 已完成：config.get/set 读写完整普通配置，credentials.set/delete/status 保存、删除及查询当前地址的配置状态，不返回密钥原文。错误配置不会覆盖有效配置，配置和密钥分别保存。

对话启动、取消与事件推送已完成：TurnManager 使用当前地址对应的文件凭据创建客户端，启动请求取得轮次标识即返回；不同任务可并行。事件仅包含展示数据，完整成功文本落库后替换预览。Core 等待异步事件处理，连接关闭时取消并等待执行结束，再关闭数据库。

历史展示查询已完成：turn.list/read/inputs/attempts 提供已保存轮次、用户输入和请求展示记录，列表支持游标分页，展示数据不包含 SDK 原始响应。历史消息与实时完成事件共用 projectMessages，保留推理正文；失败片段不进入正式消息。运行状态变化需重新读取对应记录，不能用翻页游标代替刷新。

Tauri 宿主连接已完成：开发版启动本机 Node 运行 Server，单实例窗口复用服务，读写管道独立处理，关闭输入后等待服务清理，超时终止。React 连接按 id 匹配应答并独立交付流式事件，服务退出后拒绝等待中的请求；任务列表来自真实查询。已添加 React/Vite 构建配置，发布资源封装仍待完成。

React 基本对话已完成：采用开发者提供截图中的深色侧栏、蓝色用户消息和底部输入框，连接设置支持 Base URL、模型、推理强度和密钥。新建普通任务、流式正文与推理、取消、历史切换和内存草稿均已接入；分页读取全部历史，终态刷新不会重复追加消息。系统提示词经开发者确认固定为“你是 Tilot，一个帮助用户理解和编写代码的助手。请使用用户的语言回答。”

阶段 6 的项目选择已完成：开发者确认选择目录仅保留待选项目，首次发送才创建任务并固定绑定。系统选择器取消不改变草稿，普通对话与不同项目的新对话草稿分别保留；任务按真实项目路径分组，同项目可创建新任务。Server 复用 openWorkspace 验证目录，文件、失效路径不会创建任务，目录链接解析和重开后的绑定持久化均已测试。浏览器完成模拟选择、取消、首次发送及同项目新对话检查，原生目录选择器仍需人工验收。

项目路径检查已完成：openWorkspace 从 Server 迁入 Tool，Server 直接复用，不保留重复包装。pathSegments 约定工具路径使用 / 分隔，空字符串表示根目录；resolveWorkspacePath 逐层拒绝内部链接并检查真实路径边界。开发者已确认首版跳过内部链接、不做界面文件浏览器。新增 3 项测试覆盖普通路径、非法路径和目录链接。当前检查是应用级访问约束，不能替代操作系统沙箱对并发恶意文件替换的隔离。

read 底层实现已完成：按 16 KiB 块读取，UTF-8 严格解码，保留 LF/CRLF；只返回完整行和续读位置，拒绝超长单行、无效编码、二进制控制字符及非法参数，支持取消并始终关闭文件。新增 4 项测试，覆盖分页重组、字节/行数限制、跨块中文解码、编码错误与取消。读取只检查实际读取的数据块，不扫描未读取的文件尾部。

shell 底层实现已完成：采用 Windows PowerShell 5.1，脚本 UTF-8 BOM、输出 UTF-8，不加载个人配置、不打开可见终端。限制输出尾部大小，保留原生命令非零退出码；取消和超时调用 taskkill 终止进程树，等待关闭后返回，失败不伪报成功。新增 4 项真实进程测试，包含取消后核对子进程已不存在。PowerShell 5.1 对外部程序的复杂引号参数有其原生限制，测试子进程使用脚本文件避免混淆；不另建命令字符串重写层。

read、shell 已接入模型循环：Tool 直接复用 SDK FunctionTool 类型声明，校验 JSON、字段及参数；Core 根据任务绑定决定工具可用性，成功响应先保存再按顺序执行，工具结果配对保存后重建上下文。错误参数及未知工具返回错误结果；取消和步骤限制为未执行调用保存原因。maxStepsPerRun 按模型请求次数计数，最后一步不执行无法交回模型的调用。跨历史重复标识被拒绝，终态通知失败不重跑工具。
