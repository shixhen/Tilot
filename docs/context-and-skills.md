# 上下文与项目技能

## 项目加载范围

仅对绑定项目的任务，在每次模型请求前读取：

- 项目根目录 `AGENTS.md`：全文追加到系统指令，不查找父目录、子目录或用户目录的指令。
- 项目内 `.tilot/skills/<目录名>/SKILL.md`：只自动加载 YAML 元数据中的 `name`、`description`，并附上项目相对路径。

技能文件示例：

```markdown
---
name: review-code
description: 检查当前项目的代码改动与潜在问题
---

这里是技能正文。需要使用该技能时，模型通过 read 工具读取。
```

技能正文不会自动注入上下文，也不会因此自动执行脚本。没有上述文件或目录时正常继续；无效 UTF-8、错误 YAML、缺少必要元数据或重复技能名称会明确报错。技能目录链接跳过，不通过内部链接加载外部内容。单份 YAML 元数据最多 64 KiB。

2026-10-03 起项目技能目录统一使用 `.tilot/skills`。原先放在 `.codex/skills` 的技能需要移到此目录；Tilot 不扫描其他应用的技能目录。

修改指令或技能后，下次模型请求会读取新内容；普通无项目对话不加载这些文件。不提供全局技能目录、子目录指令继承或额外技能管理界面。

## 模型限制与错误处理

2026-10-04 起，不设置应用输入预算、输出上限或安全预留量，也不再按 UTF-8 字节数估算并提前拒绝请求。Responses 请求不发送 max_output_tokens，模型服务使用自己的默认值与上下文限制；设置界面只展示模型名称。

输入包含系统策略、项目规则、技能元数据、全部回放历史、推理、工具调用及配对结果、工具声明。沿用现有历史完整性检查，不拆开工具调用与结果，不自动摘要或裁剪历史。

服务通过 HTTP 错误、response.failed 或 response.incomplete 返回超限等原因时，保存失败尝试及已收到的响应对象，结束本轮并展示错误。用户输入和原始历史保留，失败响应不用于后续回放，不自动重试。

## 代码入口

- `packages/context/src/project.ts`：根指令、技能元数据读取及指令组合。
- `packages/context/src/context.ts`：构建完整历史并校验工具调用与结果配对。
- `packages/agent-core/src/run-turn.ts`：每次请求前加载指令与技能，API 错误使用既有轮次错误流程。

YAML 使用 [yaml 库](https://eemeli.org/yaml/) 解析，支持带引号的字符串和多行描述，不自行实现 YAML 语法。
# 中断历史

启动服务时取得数据目录排他锁，再将遗留的运行中轮次和模型请求标记为 interrupted。保留原输入、已完成响应和已保存工具结果。仅对 interrupted 轮次中缺失的工具结果，在模型上下文里补充 status: unknown 的配对说明，数据库仍保留空结果；其他不完整记录继续报错。

桌面仅在最新轮次已中断时显示“继续任务”。turn.resume 创建新的轮次，保留原记录不变，由模型先核实项目状态。不会恢复旧执行栈、自动重放旧工具调用或生成摘要。正常停止和正常关闭服务仍记为 cancelled。

系统、项目和恢复提示词维护在 packages/prompts/（@tilot/prompts 包），见该目录 README.md。工具及参数的描述直接写在 packages/tool 的工具声明中。
